Q1:
- syscall was called by usertrap() inside kernel/trap.c, as stated by using bt (backtrace) of the debugger.

Q2:
- The value of p->trapframe->a7 is 15.

- p is a pointer to a struct, representing the current process running in the CPU. 
This struct is defined inside proc.h

- trapframe is the values of the registers that was reserved when CPU switched to operating a syscall.
a7 is the name of the register holding the ID of the syscall that was called.
a7 = 15 is equivalent to SYS_open

Q3:
- The value of sstatus is 0x200000022. When presented in binary, the bit 8 is 0, meaning it was previously in User mode. 
This was defined inside the official RISC-V architecture for Supervisor Status (sstatus) register.

Q4:
- In the terminal, the panic message is:
scause=0xd sepc=0x80001d4e stval=0x0
panic: kerneltrap

- In the kernel.asm, the line with the address sepc is:
num = *(int *)0;
    80001d4e:	00002683          	lw	a3,0(zero) # 0 <_entry-0x80000000>
As can be seen, the register corresponding to num is a3.

Q5:
- kernel crashed because of this line:
num = *(int *)0;
It tried to access the memory at the address 0x0, but this address isn't mapped inside the kernel's page table, which resulted in an error.

- scause = 0xd means that this is a load page fault. 
And stval = 0x0 is the invalid memory address that xv6 tried to access.
