# Question 1:

Each line printed by print_pgtbl() describes a page-table entry:
+ va: the virtual address of the page.
+ pte: the entry containing the physical page number and flags.
+ pa: the physical address extracted from the PTE.
+ perm: the low flag bits of the PTE.

V means valid, R means readable, W means writable, X means executable, U means accessible from user mode, A means accessed and D means dirty (written). User access requires U as well as the appropriate R, W or X permission.

The following explanation uses the final pgtbltest output after adding USYSCALL. Physical addresses and A/D bits can differ between runs.

+ va 0x0 contains the first page of program machine code.
perm 0x5B enables V, R, X, U and A. User mode can read and execute it, but cannot write it.

+ va 0x1000 contains the second page of program machine code.
perm 0x1B enables V, R, X and U. User mode can read and execute it, but cannot write it. A and D are clear in this snapshot.

+ va 0x2000 contains program data and BSS.
perm 0x17 enables V, R, W and U. User mode can read and write it, but cannot execute it.

+ va 0x3000 is the stack guard.
perm 0x7 enables V, R and W. U is clear, so user mode cannot access it. It catches accesses below the user stack.

+ va 0x4000 is the user stack.
perm 0xD7 enables V, R, W, U, A and D. User mode can read and write it, but cannot execute it.

+ The printed pages from va 0x5000 through 0x9000 are unmapped.
Their PTEs are zero, so V and all permission bits are clear.

+ The printed pages from va 0x3FFFFF6000 through 0x3FFFFFC000 are also unmapped.
Their PTEs are zero.

+ va 0x3FFFFFD000 is the USYSCALL page containing the current process PID.
perm 0x13 enables V, R and U. User mode can read it through ugetpid(), but cannot write or execute it.

+ va 0x3FFFFFE000 is the trapframe, which stores saved registers for trap handling.
perm 0xC7 enables V, R, W, A and D. U is clear, so the page is not accessible from user mode.

+ va 0x3FFFFFF000 is the trampoline, which contains trap entry and return code.
perm 0x4B enables V, R, X and A. U and W are clear, so it is executable in supervisor mode and is neither user-accessible nor writable.

The first 10 and last 10 printed entries contain 8 valid leaf mappings and 12 unmapped pages. Their physical addresses are not necessarily consecutive.


# Question 2:

vmprint() starts at the process's root page table, 0x0000000087f81000 in this run. vmprint_walk() recursively visits valid entries and prints the Sv39 tree. Each " .." indicates one level: level 2, level 1 and level 0. Non-leaf entries point to lower-level page-table pages.

There are 8 leaf pages in this user page table. They all use 4 KiB mappings at level 0, so each leaf line has three " .." prefixes:

 .. .. ..0x0000000000000000: pte 0x0000000021fdf85b pa 0x0000000087f7e000 RXU
Program machine code: user mode can read and execute this page, but cannot write it.

 .. .. ..0x0000000000001000: pte 0x0000000021fdec1b pa 0x0000000087f7b000 RXU
The second page of program machine code, also readable and executable from user mode, but not writable.

 .. .. ..0x0000000000002000: pte 0x0000000021fde817 pa 0x0000000087f7a000 RWU
Program data and BSS: user mode can read and write this page, but cannot execute it.

 .. .. ..0x0000000000003000: pte 0x0000000021fde407 pa 0x0000000087f79000 RW
Stack guard: U is clear, so user mode cannot access this page even though R and W are set.

 .. .. ..0x0000000000004000: pte 0x0000000021fde0d7 pa 0x0000000087f78000 RWU
User stack: user mode can read and write this page, but cannot execute it.

 .. .. ..0x0000003fffffd000: pte 0x0000000021fec413 pa 0x0000000087fb1000 RU
USYSCALL: contains the PID used by ugetpid(). User mode can read it, but cannot write or execute it.

 .. .. ..0x0000003fffffe000: pte 0x0000000021fe7cc7 pa 0x0000000087f9f000 RW
Trapframe: stores saved registers for trap handling. It is readable and writable by the kernel; U is clear, so user mode cannot access it.

 .. .. ..0x0000003ffffff000: pte 0x0000000020001c4b pa 0x0000000080007000 RX
Trampoline: contains trap entry and return code. It is readable and executable in supervisor mode, but not writable or directly accessible from user mode.

These 8 leaf mappings correspond exactly to the 8 valid entries printed by print_pgtbl() in Question 1: their virtual addresses, PTE values and physical addresses match in this run. The other 12 entries shown by print_pgtbl() are invalid and are skipped by vmprint(). Non-leaf entries printed by vmprint() describe the tree itself and are not additional code or data pages.

RXU permits user reads and execution, but not writes. RWU permits user reads and writes, but not execution. RU permits only user reads. RW and RX without U do not permit user access. vmprint() prints R/W/X/U permissions; V/A/D are explained separately in Question 1.


# Question 3:

uptime() could be made faster by storing the number of clock ticks since boot in a page that user mode can only read. The kernel would update this value on each timer tick, and a user function could read it directly instead of trapping into the kernel. Since ticks are shared by all processes, one shared physical page would avoid updating a separate copy for every process. Reads and writes of the counter must be synchronized so user mode sees a consistent value.

sbrk(0) could also benefit from the per-process USYSCALL page. This call only returns the current process memory size without changing it. The kernel could store that size in the shared page and update it whenever the size changes, including after fork and exec. A user function could then read the size directly. Calls that grow or shrink memory would still need to enter the kernel.

This approach works for calls that only read information the kernel can safely expose. The user mapping must remain read-only so programs cannot change the kernel-maintained values.


# Question 4:

The kernel page table has 95 superpage PTEs. The kernel vmprint output shows these as level-1 leaf entries with the "superpage" label:
+ 32 entries cover the 64 MiB PLIC region from 0x0c000000 to 0x10000000.
+ 63 entries cover 126 MiB of RAM from 0x80200000 to 0x88000000.
The end addresses above are exclusive. The first 2 MiB of RAM still uses 4 KiB mappings because it contains kernel text and data with different permissions. UART, virtio, the trampoline and kernel stacks also keep their 4 KiB mappings. The inspected kernel page table has 579 regular leaf PTEs.

Each 2 MiB superpage replaces 512 regular 4 KiB mappings. Without that superpage, these mappings would require one bottom-level page-table page containing 512 PTEs. Therefore, 95 superpages save 95 bottom-level page-table pages: 95 * 4096 = 389120 bytes, or 380 KiB. This is memory saved for page tables; the amount of physical memory being mapped does not change.
